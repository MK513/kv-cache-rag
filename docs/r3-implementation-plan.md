# R3 구현 계획

목표: 최신 제출 설계서의 검색/웹 도구 3종과 이해관계자 노드를 구현하고 차단 로그를 남긴다.
사용자가 제공한 R3 설계·완료 기준을 실행한다. 별도 승인 대기 없이 이 세션에서 수행한다.
공용 스키마/그래프는 R1, 코퍼스 적재는 R2, 논문 평가 함수는 R4, 최종 의미 검토는 R5 소유다.

## 1. Dense 검색과 역할 고정
- [x] 실제 소형 FAISS로 점수, 필터 누락, collection/technology 위반 실패 테스트 작성·실패 확인.
- [x] retrieve.py에 dense cosine과 엄격한 메타데이터 검사 구현.
- [x] docs.py에 역할 고정 바인더, source 호환 별칭, XML escaping 구현.
- [x] index.py의 기본 BM25 생성만 제거. R2의 파서/코퍼스는 변경하지 않는다.
- [x] 테스트 실행 및 계약 기록.

## 2. 실행별 웹 근거
- [x] 검색 snippet만 있는 경우, 403/빈 본문, redirect, 예산, 실행 격리 테스트 작성·실패 확인.
- [x] 원문 수집/추출/해시/manifest를 독립 WebEvidenceStore에 구현.
- [x] Tavily 검색 어댑터와 LangChain 도구에 실행 저장소를 바인딩.
- [x] 실패 자료가 evidence로 들어가지 않는지 파일과 반환값으로 검증.

## 3. 이해관계자 노드와 인수 증빙
- [x] 두 기술×네 주체별 출처 연결/직접 반응·추론 구분/인용 오류 재시도 테스트.
- [x] 본문 근거만 LLM에 전달하고 구조 오류·미해결 인용은 failed로 반환.
- [x] 근거 공백 보완 검색과 인용 수정은 각각 최대 1회, 결과/trace 저장.
- [x] 합성 fixture를 사용한 smoke 실행 로그, manifest, I/O JSON을 docs/evidence/r3에 생성.
- [x] 전체 pytest와 컴파일 검사, diff 검토 후 커밋 및 브랜치 게시.

## 검토할 경계
누락된 기술/관점 메타데이터는 허용하지 않는다. top_k를 먼저 잘라 허용 결과가 사라지지 않게 한다.
본문 실패를 검색 요약으로 메우지 않는다. 실행 간 cache/예산/출처가 섞이지 않아야 한다.
같은 URL의 변경 본문은 다른 근거 ID를 갖는다. 검토 전 주장을 의미 검증 완료라고 표시하지 않는다.

## 검증 환경
Python 3.11 가상환경. 테스트는 실제 FAISS와 HTML 추출·파일 기록을 사용한다.
외부 검색·HTTP·LLM 경계만 fixture로 바꾸며 실제 유료 API 검증 여부는 결과 문서에 구분한다.
